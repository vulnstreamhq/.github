# Support

Vulnstream is a private alpha without a public support service-level agreement,
monitored support address, or hosted customer service.

## Choose the right channel

| Request | Channel |
| --- | --- |
| Non-sensitive bug in an accessible repository | That repository's issue form or issue tracker |
| Documentation or organization-profile correction | A public issue in this repository |
| Product capability or design-partner feedback | The existing private evaluation channel |
| Vulnerability, credential, exploit, or data exposure | The private process in the [security policy](./SECURITY.md) |
| Dispute about an upstream CVE or CISA KEV record | The original publisher's correction process |

Do not move a security conversation into a public or broadly visible issue.

## What to include

For a product or documentation defect, include:

- the repository and tested commit or version;
- expected and observed behavior;
- the smallest safe reproduction using synthetic or public data;
- timestamps with time zone and relevant non-sensitive logs; and
- whether the problem is repeatable and any mitigation attempted.

Do not include API keys, webhook secrets, authorization headers, customer
payloads, package inventories, personal data, third-party credentials, or
unredacted infrastructure configuration.

## Current commitment

No acknowledgement, response, restoration, or resolution target is promised in
private alpha. A hosted pilot requires monitored support and security channels,
defined hours and severity levels, escalation ownership, service objectives,
and an incident-communication process before onboarding customers.
